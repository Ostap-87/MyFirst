# Форматы роликов

Формат — это заданный конвейер: какой исходник берётся, что с ним делается,
какая композиция собирается и по каким правилам. Назвали формат — дальше
можно не объяснять.

## Каталог

| Формат      | Что это                                      | Исходник                  | Готовность |
| ----------- | -------------------------------------------- | ------------------------- | ---------- |
| **Head**    | Говорящая голова: человек в кадре говорит    | своя съёмка с камеры      | обкатан    |
| **Recut**   | Плашки поверх готовой съёмки, без монтажа    | своя съёмка с камеры      | обкатан    |
| **Post**    | Ролик по посту контент-плана                 | текст поста + картинка    | работает   |
| **Cards**   | Карусель Instagram, 6–10 слайдов             | текст + генерация картинок | работает   |
| **Stats**   | Ролик на цифрах со счётчиками                | набор показателей         | каркас     |
| **Intro**   | Короткая заставка бренда                     | ничего, только тема       | каркас     |

Спросили «какие форматы есть» — показать эту таблицу и одной строкой сказать,
чем форматы отличаются по исходнику.

Прислали материал без указания формата — предложить подходящий и назвать его,
а не молча выбрать.

# Head — говорящая голова

Человек говорит на камеру. Поверх — крючок, геометка, плашки по ходу речи,
субтитры, концевая карточка. Эталон: `GTT-ChinaReel`.

## Какой шаблон брать

**Единый формат — `GTT-ChinaStories`.** Решение владельца от 25.09.2026:
все новые ролики с говорящей головой собираются на нём, а новые приёмы
добавляются в этот же шаблон по мере надобности, а не заводятся отдельным
конвейером.

| Шаблон                           | Статус                                                                 |
| -------------------------------- | ---------------------------------------------------------------------- |
| **`GTT-ChinaStories`** (Remotion) | Единый формат. Субтитры по словам, крючок, плашки, перебивки с сайта   |
| **Head-Recut** (HyperFrames)      | Заморожен. Держим ради шестнадцати уже собранных сторис, новое не делаем |

`GTT-ChinaStories` — `src/globaltechtour/compositions/ChinaStories.tsx`,
конвейер ниже по этому файлу. Новый ролик — запись `<Composition>` в
`Root.tsx` с пропсами, новый файл композиции не нужен.

**Новая фича — в ChinaStories, опциональным пропом.** Значение по
умолчанию должно давать ровно прежнюю картинку, иначе поедут все уже
зарегистрированные выпуски. Кандидаты из Recut на перенос: нижняя
однострочная плашка и замер контраста.

Head-Recut — `hyperframes/`, `npm run recut`, тексты в
`hyperframes/clips.json`, ловушки — [hyperframes/README.md](../../../remotion-video-tools/hyperframes/README.md).

**Геометрия у обоих одна** (знак на 0,135, стопка на 0,203, нижняя плашка до
1660): ролики стоят в одной ленте и должны выглядеть одинаково.

## Пул: как идёт работа с каждой задачей

Порядок, заданный владельцем. Не отступать и не сокращать.

1. **Владелец загружает пул сырых роликов.** Файлы кладутся в
   `remotion-video-tools/public/local/pool/` (папка в `.gitignore`).
   `npm run head` показывает пул и этап каждого ролика.
2. **Ролики берутся по очереди, по одному.** Следующий — только когда
   текущий дошёл до финала или владелец сказал «дальше».
3. **Подготовка** — `npm run head -- --prepare <ролик>`: поворот в
   вертикаль, паузы, студийный звук, расшифровка. Владельцу сразу:
   кадр исходника и сетку. По сетке замерить, где глаза (центр зумов),
   макушка и подбородок (куда влезают плашки). Вычитать расшифровку.
4. **Черновик** — `npm run head -- --draft <ролик> --focus <глаза>
   --hook "строка 1|строка 2"`. Скрипт расставляет идеи; дальше
   монтажёр правит `data/head/<ролик>.json` руками: автомат не видит
   смысла, противопоставлений и того, что просится на перебивку.
   Крючок — только словами из речи.
5. **Монтажный стол при владельце** — `npm run editor -- --props
   data/head/<ролик>.json`. Каждый скриншот отправлять сразу, как
   появился. Каждая идея пронумерована, на ленте — дорожка ИДЕИ, в
   превью — пунктирная рамка: какая часть кадра останется после зума,
   где встанет плашка, что закроет перебивка.
6. **Предложения таблицей** в чат: №, время, приём, на каких словах,
   где в кадре, почему. Идеи без материала (перебивка без скрина или
   B-roll) помечены — у владельца спросить материал.
7. **Ждать ответа** («убери 3», «на 5 сильнее», «ок»). Правки — в
   черновик, стол заново.
8. **Финал** — `npm run head -- --render <ролик>`, отправить, взять
   следующий ролик из пула.

### Словарь приёмов

| Приём           | В пропсах          | Когда                                                  | Длина     |
| --------------- | ------------------ | ------------------------------------------------------ | --------- |
| Быстрый зум     | `moves` `punch`    | Хук, ударное слово, цифра, имя бренда                  | 1–2 с     |
| Лёгкий наезд    | `moves` `push`     | Длинная фраза без событий, перечисление                | 2–8 с     |
| Смена кадра     | `moves` `cut`      | Новая мысль, граница фраз — как склейка со 2-й камерой | 2–4 с     |
| Плашка          | `plates`           | Цифра, термин, бренд, противопоставление (`struck` → `accent`) | до конца мысли |
| Перебивка       | `cutaways`         | Слова про сайт, маршрут, место — нужен скрин или B-roll | 2,5–4 с  |
| Карточки внахлёст | `photoCards`     | Перечисление узнаваемого: бренды, компании, продукты — карточка на каждом названии | 3–5 с |
| Всплывающие окна | `popWindows`      | «Все говорят / показывают одно и то же» — визуальный шум перед выводом | 3–4 с |
| Врезка в рамке  | `inserts`          | Доказательство: встреча, цех, выставка — «я там был» | 2–4 с |
| B-roll со шторкой | `brolls`         | Названия мест и объектов — показать, а не назвать; геометка в `caption` | 1,5–2 с на кадр |
| Деление экрана  | `splits`           | Рассказ про предмет, который надо показать, не убирая лицо: продукт, цех, страница сайта | 3–6 с |

Правила: вид кадра меняется каждые 2–4 с и не стоит дольше 6 с; между
движениями камеры не меньше 0,8 с чистого кадра; хук — всегда быстрый
зум с нуля; плашки — не раньше 2,9 с (до этого на их месте крючок);
последние 2 с — чистый кадр или зум под призыв; центр зумов — на глазах;
после блока с врезками — чистый кадр с одним лицом (ритм «графика —
лицо»); лица знаменитостей во врезках не использовать — право на
изображение. Витрина всех приёмов — композиция `GTT-Arsenal`, деления экрана —
`GTT-SplitDemo`.

## Монтажный стол и скриншоты по ходу

Владелец хочет видеть, как собирается ролик, а не только итог. Поэтому
к каждому новому ролику ChinaStories:

    npm run editor -- --id GTT-Invite            скриншоты + видео стола
    npm run editor -- --id GTT-Invite --stills   только скриншоты

Результат — `out/editor/<id>/`: скриншот стола в момент каждого события
(крючок, каждая плашка, каждая перебивка, финал), `sheet.jpg` — все
одним листом, `editor.mp4` — стол целиком со звуком. Сверху идёт сам
ролик, справа — что сейчас в кадре, снизу — лента как в CapCut: курсор
стоит, дорожки ВИДЕО (с волной громкости), КРЮЧОК, ПЛАШКИ, САЙТ, СЛОВА
едут под ним.

Скрипт печатает `СКРИН <путь>` на каждый готовый кадр. **Отправлять
скриншоты владельцу по мере появления**, не дожидаясь конца рендера:
на каждом шаге конвейера (после подтяжки, после расшифровки, стоп-кадры
с плашками, итог) он должен видеть промежуточный результат.

**Recut считается медленно** — около 20 секунд машинного времени на секунду
видео. Пакет из шестнадцати роликов идёт полтора-два часа, это фоновая
задача, а не ожидание в диалоге.

Полный метод с объяснением каждого правила —
[remotion-video-tools/docs/talking-head.md](../../../remotion-video-tools/docs/talking-head.md).
Здесь порядок действий.

## Конвейер

Порядок важен: каждый шаг меняет тайминги следующего.

### 1. Взять исходник с камеры

Не из Kapwing, CapCut и прочих онлайн-редакторов. Оттуда приходит чужой
водяной знак, вшитые титры, ужатое разрешение и уже изменённый темп.

Спросить прямо: «есть ли файл прямо с телефона». Если нет — работать с тем,
что дали, но сказать, чем это обойдётся.

### 2. Разобрать исходник

```bash
ffprobe -v error -show_entries stream=width,height,r_frame_rate,codec_name \
  -show_entries format=duration -of default=nw=1 <файл>
```

Проверить: разрешение, поворот (iPhone пишет горизонталь с матрицей −90),
звук, длительность, вшитые титры, склейки.

### 3. Подтянуть: вырезать паузы и заполнители

```bash
npm run tighten -- --video public/local/<файл>.mp4 --dry-run
npm run tighten -- --video public/local/<файл>.mp4 --out public/local/<файл>-tight.mp4
```

Это **обязательный шаг**, а не опция. В живой речи на улице пауз обычно
15–20% хронометража: на эталонном ролике 6,4 секунды из 34,2.

- Паузы **укорачиваются**, а не убираются: речь без пауз звучит роботом.
- Заполнители («ээ», «ммм») режутся по расшифровке — нужен флаг `--captions`.
- Мусорные слова («ну», «вот», «типа») — только через `--junk`, осознанно:
  это полноценные слова, и вслепую их резать значит портить интонацию.
- Порог тишины на уличной съёмке подбирается: шум машин держит фон высоко.
  По умолчанию −40 dB, смотреть по `--dry-run`.

**Сначала подтянуть, потом всё остальное.** Вырезание сдвигает тайминги.

### 4. Уложить в длительность

Посмотреть, **что попадёт под нож**, прежде чем резать. Главное в записи
почти всегда в конце.

Не влезает — ускорить, а не обрезать:

```bash
ffmpeg -i in.mp4 -filter_complex \
  "[0:v]setpts=PTS/К[v];[0:a]atempo=К,loudnorm=I=-14:TP=-1.5:LRA=11[a]" \
  -map "[v]" -map "[a]" -r 30 out.mp4
```

где `К = длительность / нужная_длительность`. После шага 3 коэффициент
обычно близок к единице, и речь звучит естественно.

### 5. Убрать блеск с лица

Сначала замерить, сколько выбито в белое. Больше нескольких процентов —
детали не вернуть.

```bash
[0:v]format=yuv444p,split=3[base][soft][m];
[soft]boxblur=26:1,curves=all='0/0 0.5/0.5 0.75/0.70 1/0.88'[sb];
[m]format=gray,geq=lum='clip((lum(X,Y)-175)*3.4,0,255)',boxblur=26:1,format=yuv444p[mask];
[base][sb][mask]maskedmerge,eq=saturation=1.04
```

Кривые сами по себе не годятся: тянут весь кадр, а блик локальный.

### 6. Расшифровать и вычитать

```bash
npm run transcribe -- --audio public/local/<файл>.wav --model small --language ru \
  --out data/captions-<тема>.json
```

Расшифровка уходит в кадр субтитрами — ошибка распознавания станет ошибкой
в ролике. Вычитывать обязательно, особенно названия и имена.

### 7. Найти опорные секунды

Из расшифровки достать, когда звучат названия, места, цифры. Плашки ставятся
по этим секундам, никогда на глаз.

### 8. Собрать композицию

Копировать `src/globaltechtour/compositions/ChinaReel.tsx` и править под тему.
Что в ней есть:

- крючок первые 2 секунды, обещает то, что прозвучит в конце;
- геометка гарамоном (`Cormorant Garamond`) с плашкой;
- логотип с вращающимся тетраэдром (`SpinningTetra`) в шапке;
- плашки по таймингам, **копятся** а не сменяются;
- субтитры на плечи, ниже подбородка и выше 1600 px;
- концевая карточка: белый фон, фирменный синий, крупный логотип.

Место для плашек выбирать **примеркой на реальных кадрах** тех секунд, когда
они появятся, а не по сетке.

### 9. Проверить стоп-кадрами

```bash
npx remotion still <композиция> out/f.png --frame=N
```

Секунды против минут полного рендера. Ловит уехавший текст, нечитаемые
надписи, перекрытия.

### 10. Отрендерить и положить в очередь

```bash
npx remotion render <композиция> out/<имя>.mp4
npm run q:add -- --channel instagram --brand gtt --video out/<имя>.mp4 --at "..."
```

## Что подбирается пропами, а не кодом

`logoScale`, `logoSpin`, `hookTop`, `hookBottom`, `place`, `hasBurnedCaptions`.
Полный рендер — минуты, фрагмент в 150 кадров — секунды:

```bash
npx remotion render <композиция> out/test.mp4 --frames=0-149 --props='{"logoSpin":72}'
```

# Post — ролик по посту

Вертикальный ролик из поста контент-плана: картинка с медленным наездом,
заголовок, лид, призыв. Композиции `GTT-PostReel`, `Aura-PostReel`.

```bash
npm run parse-plan
npm run render-batch -- --brand gtt --limit 3 --dry-run
```

Без звука и субтитров — это не разговорный формат. Если нужен голос,
это уже Head.

# Cards — карусель Instagram

6–10 слайдов PNG 1080×1350, каждый листается отдельно.

```bash
npm run carousel -- --slug <тема> --points 3
npm run q:add -- --channel instagram --brand gtt --carousel <тема> --at "..."
```

Правила слайдов — в `CLAUDE.md`, раздел «Карусели Instagram». Главное:
главное держать в центральном квадрате, сборка из поста — черновик.

# Stats и Intro

Каркасы. `GTT-Stats` — горизонтальный ролик на счётчиках `CountUp`,
`*-Intro` — короткая заставка. Под конкретную задачу дорабатываются.

## Общее для всех форматов

- Бренд определяет палитру и шрифты целиком, смешивать нельзя (`CLAUDE.md`).
- Тяжёлые исходники — в `public/local/`, она в `.gitignore`.
- В репозиторий идут код и расшифровка: по ним ролик пересобирается.
- Готовый ролик кладётся в очередь канала, а не остаётся в `out/`.
