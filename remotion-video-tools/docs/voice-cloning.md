# Клонирование голоса: что работает, а что нет

Проверено на записи владельца GTT (53 с русской речи, `public/local/voice.mp4`).

## Принятая схема работы

**Синтез идёт через Higgsfield в диалоге с ассистентом, доводка — скриптом.**
Владелец пишет текст, ассистент делает дубль его голосом, дальше
`npm run speak -- --in <дубль> --fit <секунды>` доводит до дорожки для
композиции.

Платных подписок это не требует: слепок уже загружен, дубль стоит 5 кредитов.
Единственное ограничение — первый шаг нельзя запустить командой, потому что
у Higgsfield нет публичного API для речи (разбор ниже).

Режим `npm run speak --text` написан под ElevenLabs и **не используется** —
он ждёт ключа на случай, если схема поменяется. Работоспособность этой
половины не проверена: ключа нет.

## Итог замеров

| Язык      | Модель            | Образец                | Результат |
| --------- | ----------------- | ---------------------- | --------- |
| английский | Seed Audio 1.0    | русская запись          | **работает**, whisper разбирает слово в слово |
| китайский | Seed Audio 1.0    | русская запись          | не язык вообще: whisper выдаёт `(台語)` |
| китайский | Seed Audio 1.0    | английский дубль клона  | то же самое: `(字幕製作:…)`, классическая галлюцинация на неразборчивом |
| китайский | Seed Audio 1.0    | без образца, свой голос | **работает**, текст распознаётся полностью |

Вывод: клон Seed Audio тянет за собой фонетику языка образца. Английский
к русскому достаточно близок, чтобы артикуляция не разъехалась. Китайский —
нет: тонов и слогов, которых в русской речи не встречается, модели взять
неоткуда, и она синтезирует нечто на русской фонетической базе.

**Подмена образца не лечит.** Английский дубль — это уже нерусская
артикуляция в нужном тембре, и всё равно китайский не вышел. Значит,
ограничение в самой модели, а не в материале.

## Как проверять, а не слушать

Синтез на незнакомом языке нельзя принимать на слух: непонятно, плохой это
акцент или не тот язык. Проверка — прогнать через whisper:

```bash
npm run transcribe -- --audio <файл> --language zh --out /tmp/probe.json
```

Разбирает текст — язык настоящий. Выдаёт `(台語)`, `(字幕製作:…)` или пустоту —
это не речь на этом языке, и дальше тратить генерации незачем.

## Готовый конвейер: озвучка его голосом

Образец лежит в хранилище Higgsfield и **повторно не загружается** — у него
постоянный идентификатор:

    media_id: 5cee8b32-36ce-4ada-b71e-12a1d7ec322c

Загружал его сам владелец через виджет `create_voice`: запись голоса наружу
не отдаётся автоматикой, и это правильно. Один раз загруженный образец
годится для любого числа дублей.

Голос как отдельную сущность в аккаунте создать не вышло — упирается в лимит
(`Voice limit reached`). Он и не нужен: Seed Audio клонирует прямо из образца.

### Шаги

1. **Синтез** — `generate_audio`, модель `seed_audio`:

       model: seed_audio
       medias: [{ value: 5cee8b32-…, role: audio_references }]
       sample_rate: 48000, format: wav
       speech_rate: подбирается под хронометраж

2. **Подтяжка пауз** — только если дубль длиннее нужного:

       ffmpeg -i in.wav -af "silenceremove=stop_periods=-1:stop_duration=0.35:stop_threshold=-35dB:detection=peak" out.wav

3. **Студийная чистка** — `npm run voice -- --in <дубль> --out public/audio/<имя>.wav`.
   Та же цепочка, что и для живой записи: синтез приходит к −16 LUFS так же.

4. **Расшифровка** — `npm run transcribe -- --audio <дорожка> --language en`.
   Она идёт и в субтитры, и в нарезку сцен.

Стоимость дубля — 5 кредитов, около минуты ожидания.

### Языки

Английский проверен и работает. Русский — родной для образца. Китайский не
получается, разбор ниже.

## `npm run speak`: текст → готовая дорожка

    npm run speak -- --text "Реплика" --voice <id>
    npm run speak -- --text-file data/promo-script-en.md --voice <id> --fit 44.6 --captions
    npm run speak -- --in out/tts/dubl.wav --fit 44.6      доводка готового дубля
    npm run speak -- --clone public/local/sample.mp3 --name "Ostap GTT"
    npm run speak -- --voices                              что есть в аккаунте

Скрипт делает всё, что раньше делалось руками: синтез, укладку в
хронометраж, студийную чистку той же цепочкой, что и живые записи, и
расшифровку в субтитры.

### Почему ElevenLabs, а не Higgsfield

**У Higgsfield нет публичного API для речи.** В его спецификации восемь
endpoint'ов, все про изображения и видео; Seed Audio живёт только внутри MCP.
Подключение, которым пользуется ассистент, — это MCP-коннектор: сессия
аккаунта, которую держит Claude, а не ключ, который можно положить в секреты.
Ключи `HF_API_KEY_ID`/`HF_API_KEY_SECRET` с console.higgsfield.ai существуют,
но речь через них не вызывается.

Отсюда разделение: голос, склонированный в Higgsfield, доступен только в
диалоге с ассистентом. Скриптом — только ElevenLabs.

### Режим без ключа

`--in <файл>` работает всегда: берёт готовый дубль, откуда бы он ни пришёл —
хоть из Higgsfield через ассистента, — и доводит до дорожки для композиции.
Это половина работы, которая от поставщика синтеза не зависит.

### Укладка в хронометраж

`--fit 44.6` подбирает длину пауз делением пополам: десять проходов ffmpeg,
точность до сотых. Проверено на английском дубле — 44,23 с уложились в 42,01
при цели 42,0.

Паузы **укорачиваются, а не вырезаются**: речь без них звучит загнанной, и
на слух это хуже лишней секунды.

### Что нужно завести один раз

1. Подписка ElevenLabs уровня **Starter ($6/мес)** — с неё начинается Instant
   Voice Cloning и коммерческая лицензия. На бесплатном тарифе нет ни того,
   ни другого. Creator ($22) нужен только ради Professional Voice Clone.
2. Ключ: `elevenlabs.io` → профиль → API Keys.
3. Ключ в секреты репозитория: `Settings → Secrets and variables → Actions`,
   имя `ELEVENLABS_API_KEY`. **В файлы ключ не класть.**
4. Клон голоса — один раз:

       npm run speak -- --clone public/local/voice-sample.mp3 --name "Ostap GTT"

   Вернёт `voice_id`. Дальше он подставляется в `--voice`.

Образец для клонирования обрабатывается по минимуму: срез ниже 80 Гц и
громкость, без компрессора и шумодава. Чем длиннее образец, тем лучше клон:
53 секунды дают рабочий результат, 25-30 минут — Professional Voice Clone,
который заметно устойчивее на чужих языках.

## Что нужно для китайского его голосом

Seed Audio не подходит. Нужен клон, обученный на голосе как таковом, а не
подстроенный под один образец на лету:

- **ElevenLabs Professional Voice Clone** — 25-30 минут чистой записи,
  `eleven_multilingual_v2` умеет 74 языка, включая китайский. Тариф Creator ($22),
  ключ в секретах репозитория как `ELEVENLABS_API_KEY`. Коннектор в MCP
  клонировать не умеет — только через API.
- **Запись по-китайски.** Если владелец начитает 30-60 с китайского текста,
  даже с акцентом, Seed Audio получит нужную фонетику. Качество непредсказуемо.

## Бесплатная альтернатива, если схема перестанет устраивать

Локальная модель с клонированием по образцу, без сервисов. Контейнер её
тянет: 20 ГБ диска, 15 ГБ памяти, Python 3.11.

**Лицензии тут важнее качества.** XTTS-v2 — самая известная и лучшая по
звуку — выпущена под CPML и **запрещена для коммерческого использования**.
Ролики GTT коммерческие, поэтому она не годится, хотя все инструкции в сети
советуют именно её. Брать из MIT-лицензированных: Chatterbox (Resemble AI)
или связку OpenVoice v2 + MeloTTS.

У связки есть побочная выгода: она сначала синтезирует речь движком нужного
языка, а потом переносит тембр. Китайский, на котором Seed Audio споткнулся,
так может и получиться.

Не делалось: владелец выбрал оставить текущую схему.

## Хронометраж: считать, а не прикидывать

Скорость речи у моделей разная, и прикидка «слов в секунду» промахивается.

| Дорожка             | Сырая длина | После подтяжки пауз |
| ------------------- | ----------- | ------------------- |
| русская, живая      | 54,0 с      | 42,15 с             |
| ElevenLabs, англ.   | 46,5 с      | 41,6 с              |
| Seed Audio, англ. `speech_rate=0`  | 59,4 с | 49,0 с |
| Seed Audio, англ. `speech_rate=9`  | 44,2 с | 38,7 с |
| Seed Audio, англ. `speech_rate=18` | 37,6 с | 35,6 с |

**`speech_rate` у Seed Audio нелинеен**: от 0 до 9 длина падает на 15 секунд,
от 9 до 18 — всего на 7. Подбирать двумя-тремя пробами, а не расчётом.

Взят `speech_rate=9` без подтяжки: сырые 44,2 с сами попали в 44,65 с русской
дорожки, а паузы там ровные (0,33-0,78 с), стопориться негде.

## Подтяжка пауз

```bash
ffmpeg -i in.wav -af "silenceremove=stop_periods=-1:stop_duration=0.35:stop_threshold=-35dB:detection=peak" out.wav
```

`stop_duration` — до какой длины укорачиваются паузы, не порог срабатывания.
Подбирается под нужный хронометраж: у китайской дорожки 0,45 дало 45,7 с,
0,35 — 44,4 с.

## Обработка — после синтеза, не до

Образец для клонирования обрабатывается по минимуму: срез ниже 80 Гц и
громкость. Компрессор, шумодав и деэссер из `npm run voice` клонер скопировал
бы вместе с голосом. Студийная цепочка накладывается на **готовую** дорожку —
и на синтезе работает так же, как на живой записи: обе пришли к −16 LUFS.
