# Каналы: что подключено и что нужно для остальных

Структура одинакова для всех: **канал → бренд → очередь**. У каждого бренда
свой аккаунт в каждой сети, поэтому и папка, и токен у него свои.

```
<канал>/<бренд>/
  queue.json      что и когда публикуется — одна очередь на аккаунт
  published.json  что уже вышло, когда, под каким id
  photo/<дата>-<тип>-<тема>/   карусели и фото
  video/<дата>-<тип>-<тема>/   ролики
```

Файлы разведены по виду, потому что это разные производственные процессы.
Очередь общая: она описывает расписание ленты, а лента у аккаунта одна.

| Канал     | Бренды            | Статус                          | Типы контента               |
| --------- | ----------------- | ------------------------------- | --------------------------- |
| Instagram | GTT, Aura, личный | **подключён**                   | `carousel`, `reel`          |
| YouTube   | GTT, Aura, личный | папки готовы, публикации нет    | `short`, `video`            |
| Threads   | GTT, Aura, личный | папки готовы, публикации нет    | `carousel`, `image`, `text` |
| TikTok    | GTT, Aura, личный | папки готовы, публикации нет    | `video`                     |
| Telegram  | GTT, Aura         | работает отдельно (`tg-images`) | картинки к постам           |

Контент можно ставить в очередь **до** того, как подключена публикация: он
дождётся её в папке канала.

## Instagram — подключён

Официальный Graph API. Что настроить и какие лимиты — в
[publishing.md](./publishing.md). Секреты: `IG_TOKEN_<БРЕНД>` и
`IG_USER_<БРЕНД>`, где бренд — `GTT`, `AURA`, `PERSONAL`.

## YouTube — что понадобится

**YouTube Data API v3**, загрузка методом `videos.insert`.

- Проект в Google Cloud, включённый YouTube Data API, OAuth-клиент.
- Refresh-token на каждый канал: у каждого бренда свой аккаунт Google.
- **Главное ограничение — квота.** По умолчанию 10 000 единиц в сутки на
  проект, одна загрузка стоит 1600. То есть примерно **6 роликов в сутки на
  весь проект**, а не на канал. Если три бренда публикуются одновременно,
  квоту придётся расширять заявкой в Google.
- Shorts — это обычная загрузка видео вертикального формата до 3 минут;
  отдельного API у Shorts нет.

## Threads — что понадобится

**Threads API** (отдельный от Instagram, хотя тоже Meta). Порядок публикации
такой же двухшаговый: создать контейнер, затем опубликовать.

- Аккаунт Threads привязан к Instagram, но токен нужен **свой** —
  от Threads API, разрешение `threads_content_publish`.
- Подпись короче: **500 символов** против 2200 у Instagram. Текст под
  Instagram в Threads не влезет — для него нужна отдельная версия.
- Карусель — до 20 элементов.

## TikTok — два пути

**Content Posting API** напрямую: приложение в TikTok for Developers,
разрешение `video.publish`. Заявка проходит ручную проверку, до одобрения
видео публикуются только в приватном режиме — это главный подводный камень.

**Через Higgsfield**, который у вас уже подключён: в нём есть готовые
инструменты `tiktok_connect`, `tiktok_prepare_publish` и
`tiktok_publish_status`. Аккаунт подключается один раз, отдельная заявка в
TikTok не нужна. Для трёх брендов понадобится три подключённых аккаунта.

Второй путь быстрее, но публикация идёт через сторонний сервис — решать вам.

## Как добавить канал в реестр

Каналы и бренды описаны в `scripts/channels.mjs`. Новый канал — это запись
в `CHANNELS` с типами контента и лимитами; папки и пустые очереди создаются
автоматически при первом обращении. Публикация пишется отдельным скриптом
`publish-<канал>.mjs` — очередь, архив и статусы берутся из общего модуля,
заново их реализовывать не нужно.
