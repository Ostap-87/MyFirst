# Правила проекта

Remotion-проект (React + TypeScript) для трёх независимых брендов:
**GlobalTechTour (GTT)**, **Aura Robotics**, **ostapdotcenko** (личный бренд).

## Выбор бренда

1. Если в задаче упомянут бренд — используй **только** `theme.ts`, шрифты и
   ассеты его папки. Не смешивай стили разных брендов в одной композиции.

   | Слова в задаче                              | Папка                 | Префикс композиций |
   | ------------------------------------------- | --------------------- | ------------------ |
   | «GTT», «тур», «делегация», «globaltechtour» | `src/globaltechtour/` | `GTT-*`            |
   | «Aura», «робот», «robotics»                 | `src/aura-robotics/`  | `Aura-*`           |
   | «личный бренд», «ostapdotcenko», «блог»     | `src/ostapdotcenko/`  | `Personal-*`       |

2. Если бренд не назван явно, но идёт правка уже открытой или последней
   обсуждаемой композиции — продолжай в её контексте, сам не переключайся.
3. Если контекст не ясен вообще — спроси, для какого из трёх брендов задача,
   прежде чем писать код.

## Эффекты

4. Новый визуальный эффект (переход, анимация появления, моушн-приём) всегда
   создавай в `src/shared/components/effects/` как отдельный переиспользуемый
   компонент с Zod-схемой параметров — **никогда** не пиши анимацию inline
   внутри композиции конкретного бренда.
   Создавать через `npm run new-effect -- --name MyEffect --what "что делает"`,
   соглашения — в `src/shared/components/effects/README.md`.

## Что спрашивать, а что делать сразу

5. Перед структурными изменениями — новая папка верхнего уровня, смена стека,
   смена версии Remotion, новая зависимость — спрашивай подтверждение.
   Точечные правки (текст, цвет, тайминг, параметр существующего компонента) —
   делай сразу.

## Разбор моушн-дизайна из референсных видео

Когда прислали ссылку или файл чужого видео с эффектом, который нужно повторить:

1. **Кадры.** Если это файл — разбей нужный фрагмент через ffmpeg:
   `ffmpeg -i ref.mp4 -ss <старт> -t <длительность> -vf fps=30 frames/frame_%03d.png`.
   Если это ссылка — скачай фрагмент или попроси файл.
2. **Опиши движение словами по кадрам:** что движется, откуда куда
   (позиция / масштаб / прозрачность / поворот), с какой кривой
   (плавно / пружина / резко), сколько это длится в секундах **и кадрах**.
3. **Напиши компонент-эффект** в `src/shared/components/effects/` через
   `npm run new-effect`, используя `interpolate` и `spring` под замеренные тайминги.
4. **Отрендери тестовый кадр или фрагмент** на нейтральных данных:
   `npx remotion still Shared-EffectsLab out/test.png --frame=<кадр>`.
5. **Сравни свой рендер с кадрами референса** — позиция, скорость, тайминг.
   Заметно расходится — поправь параметры кривой и повтори рендер.
6. **Авторские права.** Если референс — узнаваемый фирменный приём конкретной
   студии или бренда (не общий тип эффекта, а уникальная реализация) — спроси,
   делать точную копию или «в похожем духе», прежде чем продолжать.

Результат сохраняй как обычный эффект — со временем из этого и складывается
библиотека. Пример полного разбора — `docs/reference-breakdown.md`
(разговорный Reels: субтитры, номера пунктов, переписка, призыв, финал).

**Для раскадровки нужен системный ffmpeg.** Встроенный `npx remotion ffmpeg`
собран урезанным: фильтров `scale` и `tile` в нём нет, контактный лист им не
сделать.

## Команды

| Команда                                                                         | Что делает                                                                     |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `npm run dev`                                                                   | Remotion Studio: превью всех композиций                                        |
| `npm run new-effect -- --name X --what "…"`                                     | Новый эффект + экспорт + строка в README                                       |
| `npm run new-composition -- --brand aura --name Y [--format vertical]`          | Новая композиция бренда + регистрация в `Root.tsx`                             |
| `npm run set-theme -- --brand gtt --key colors.accent --value "#2563eb"`        | Точечно меняет одно значение в `theme.ts` (без `--value` — показывает текущее) |
| `npm run parse-plan`                                                            | Разбирает контент-план Telegram-постов в `data/posts.json`                     |
| `npm run render-batch -- --brand gtt --limit 3`                                 | Пакетный рендер вертикальных роликов по постам (`--dry-run` — только план)     |
| `npm run transcribe -- --audio <файл>`                                          | Пословные субтитры из аудио локальным whisper.cpp                              |
| `npm run speak -- --text "…" --voice <id>`                                      | Озвучка текста: синтез, укладка в хронометраж, чистка, субтитры                |
| `npm run tighten -- --video <файл>`                                             | Режет паузы и мычание (`--dry-run` — только план)                              |
| `npm run join -- --plan data/series.json`                                       | Склеивает готовые ролики в один с переходами (`--dry-run` — только план)       |
| `npm run make-sfx`                                                              | Генерирует UI-звуки в `public/audio/sfx` (ffmpeg, без лицензий)                |
| `npm run carousel -- --slug <slug>`                                             | Карусель Instagram в PNG: из поста контент-плана или из файла слайдов          |
| `npm run q:add -- --channel instagram --brand aura --carousel <имя> --at "..."` | Кладёт готовый контент в очередь канала                                        |
| `npm run q`                                                                     | Весь план по каналам и брендам: очередь и архив                                |
| `npm run publish -- --due`                                                      | Публикует посты, у которых наступило время (`--dry-run` — только план)         |
| `npm run lint`                                                                  | ESLint + `tsc --noEmit`                                                        |
| `npx remotion render <id> out/<id>.mp4`                                         | Рендер видео                                                                   |
| `npx remotion still <id> out/<id>.png --frame=N`                                | Рендер одного кадра                                                            |

Форматы `--format`: `landscape` (1920×1080), `vertical` (1080×1920), `square` (1080×1080).
Бренды в `--brand`: `gtt`, `aura`, `personal` (принимаются и полные имена папок).

## Форматы кадра и безопасные зоны

Ролики делаются под три формата: 16:9, 9:16 и 1:1 / 4:5.

- **Размеры задавай долей кадра**, а не пикселями: `const { fs, sp } = useFormat()`,
  дальше `fontSize: fs(0.08)` — 8% ширины. Кегль в пикселях, подобранный на
  кадре 1920, в кадре 1080 выглядит вдвое крупнее положенного.
- **Текст оборачивай в `<SafeArea platform="telegram" />`** (`telegram`, `reels`,
  `shorts`, `landscape`, `feed`). В вертикали низ кадра перекрыт подписью и
  кнопками — заголовок «по центру» на телефоне уезжает под интерфейс.
  Проп `guides` рисует границы зоны прямо в Studio.

## Данные: ролики из контент-плана

`npm run parse-plan` разбирает `../tg-images/20-day-batch.md` в `data/posts.json`
(дата, бренд, компания, slug, заголовок, лид, CTA, путь к картинке с учётом
версий `-v2`, кандидаты-числа для счётчика). `npm run render-batch` рендерит по
этим данным вертикальные ролики, собирая бандл один раз на весь пакет.

Картинки берутся из `tg-images` через симлинк `public/tg-images`: `staticFile`
видит только содержимое `public`, поэтому новые источники ассетов подключай
так же, а не абсолютным путём.

## Субтитры

`npm run transcribe -- --audio <файл> --model small --language ru` даёт
`data/captions.json`. Что важно знать:

- **Скрипт склеивает под-словные токены в слова.** whisper режет «выложил» на
  «вы|лож|ил»; в режиме одного слова в кадре это обрывки. Сырые токены —
  флаг `--raw-tokens`, логика склейки — `src/shared/captions.ts` (и её копия
  для скриптов в `scripts/captions-utils.mjs`, правите одну — правьте обе).
- **Хвост дорожки вычитывай глазами.** На музыке и шуме whisper дописывает
  фразу, которой в речи нет. Скрипт отдельно показывает слова с низкой
  уверенностью.
- **Гарнитура и оформление — пропсами**, не правкой кода: `captionFont`
  (Onest, Inter, Golos Text, Montserrat, Manrope) и `captionStyle`
  (`shadow`, `outline`, `plate`). Почему именно эти — в
  `docs/reference-breakdown.md`.

## Форматы роликов

У роликов есть именованные форматы — заданные конвейеры «какой исходник,
что с ним делается, какая композиция». Каталог и конвейер каждого —
в навыке [.claude/skills/video-format/SKILL.md](../.claude/skills/video-format/SKILL.md).
Назвали формат («сделай Head») — дальше объяснять не нужно.

| Формат  | Что это                        | Исходник                   |
| ------- | ------------------------------ | -------------------------- |
| `Head`  | говорящая голова               | своя съёмка с камеры       |
| `Post`  | ролик по посту контент-плана   | текст поста + картинка     |
| `Cards` | карусель Instagram             | текст + генерация картинок |
| `Stats` | ролик на цифрах                | набор показателей          |
| `Intro` | заставка бренда                | только тема                |

## Head: говорящая голова

Полный метод — [docs/talking-head.md](./docs/talking-head.md): тринадцать
правил, каждое выведено из конкретной ошибки на разборе `GTT-ChinaReel`.
Коротко, что важнее всего:

- **Паузы и мычание вырезаются первым делом** (`npm run tighten`). В живой
  речи на улице их 15—20% хронометража. Паузы укорачиваются, а не убираются
  совсем; мусорные слова («ну», «вот») — только осознанно через `--junk`.
  После подтяжки нужное ускорение падает почти до единицы.
- **Порядок шагов не переставлять**: каждый сдвигает тайминги следующего.
  Расшифровка — после подтяжки и ускорения.
- **Исходник берём с камеры, не из онлайн-редактора.** Файл из редактора
  приносит чужой водяной знак, вшитые титры, ужатое разрешение и изменённый
  темп — всё это потом маскируется костылями.
- **Перед обрезкой смотрим, что попадёт под нож.** Если речь не влезает в
  нужную длительность — ускоряем через `atempo`, а не режем смысл.
- **Тайминги плашек — из расшифровки**, и расшифровку обязательно вычитываем:
  она уходит в кадр субтитрами.
- **Место для плашек выбираем примеркой на реальных кадрах** тех секунд,
  когда они появятся.
- **Стоп-кадры до полного рендера.** `npx remotion still` занимает секунды,
  полный рендер — минуты.

## Материалы роликов

Съёмка, звук и субтитры приходят в композицию **путями в пропсах**
(`footageSrc`, `audioSrc`, `captionsSrc`), а не импортом в коде: один выпуск —
одна команда рендера, без пересборки. Субтитры грузит `useCaptions` через
`delayRender`, длительность считает `calculateMetadata` по последнему слову.

Тяжёлые и чужие исходники кладём в **`public/local/`** — она в `.gitignore`.
Чужие материалы (референсы, чужая речь) в репозиторий не коммитим вообще.

## Карусели Instagram

`npm run carousel` рендерит карусель набором PNG 1080×1350 — Instagram
принимает её именно файлами, по одному на слайд.

```bash
npm run carousel -- --input data/carousel.example.json   # по своему сценарию
npm run carousel -- --slug nio-battery-swap --points 3   # из поста контент-плана
npm run carousel -- --slug ... --square --no-hint        # 1:1, без «листай»
```

- **Слайд — не кадр видео.** Типы слайдов (`cover`, `point`, `metric`,
  `quote`, `image`, `cta`) заданы схемой: каждый листают отдельно, и каждый
  должен читаться без соседних. Свободной вёрстки «как в макете» тут нет.
- **Главное держи в центральном квадрате.** В ленте слайд 4:5 виден целиком,
  но в сетке профиля обрезается до 1:1 по центру — верхние и нижние 10%
  высоты там не видно. Поля берёт `SAFE_AREAS.carousel`.
- **Сборка из поста — черновик, а не результат.** Автоматика вытаскивает
  цифру, режет текст на пункты и собирает призыв, но заголовки почти всегда
  стоит переписать руками. Годы (1900–2100) из метрик отфильтрованы:
  «работает с 2008 года» — это не показатель.
- **Скрипт чистит папку перед рендером.** Иначе короткая карусель оставляет
  хвост от прошлой длинной, и лишний слайд уезжает в публикацию. Сохранить
  старые файлы — флаг `--keep`.

## Каналы: хранилище, очередь, расписание

Весь контент лежит в **`content/`** — одно место на все каналы. Структура
одинакова для всех: **канал → бренд → вид**:

```
content/instagram/globaltechtour/
  queue.json        очередь аккаунта: что и когда
  published.json    архив вышедшего
  photo/2026-09-25-carousel-robotics-expedition/
  video/2026-09-26-reel-china-hook/
content/instagram/aura/ content/instagram/personal/
content/youtube/ content/threads/ content/tiktok/   публикация ещё не подключена
```

Telegram — исключение: он лежит в `tg-images/` вне `content/`, потому что его
картинки уже разосланы и на них ссылаются по вшитым raw-ссылкам. Переносить
его нельзя, пока не перевешены ссылки.

**Путь поста строится только через `postPath()` и `channelDir()` в
`scripts/channels.mjs`.** Не собирайте его из строк в других местах: по нему
Instagram скачивает медиа, и расхождение означает пост без картинок.

- **У каждого бренда свой аккаунт**, поэтому своя папка и свой токен:
  `IG_TOKEN_GTT`, `IG_TOKEN_AURA`, `IG_TOKEN_PERSONAL`. Пост лежит в папке
  того аккаунта, куда пойдёт, — перепутать нельзя. По той же причине
  `--post` требует явного `--brand`.
- **Файлы разведены по виду: `photo/` и `video/`.** Это разные процессы —
  карусель собирается рендером слайдов, ролик монтируется со звуком и
  субтитрами. Вид определяется типом автоматически (`MEDIA_KINDS` в
  `channels.mjs`) и пишется в `meta.json`.
- **Очередь одна на аккаунт**, а не на вид: она описывает расписание ленты,
  а лента у аккаунта одна. С двумя очередями легко поставить карусель и
  ролик на одно время и выдать два поста подряд.
- **Имя папки: `<дата>-<тип>-<тема>`.** Тип (`carousel`, `reel`, `video`,
  `short`) виден из списка, дата первой — архив читается хронологически.
- **Папка поста не удаляется после выхода.** По архиву видно, что именно
  было опубликовано.
- **Ссылки не переиспользуются.** Пересобрали карусель — новая папка, а не
  перезапись: площадки кэшируют медиа, подмена файла ломает вышедший пост.
- **Новый канал — запись в `scripts/channels.mjs`** (типы, лимиты, префикс
  секретов) плюс скрипт `publish-<канал>.mjs`. Очередь, архив и статусы
  берутся из общего модуля, заново их писать не нужно. Что требуется для
  YouTube, Threads и TikTok — в `docs/channels.md`.
- **Токены только в секретах репозитория.** В файлы их не класть никогда.

## Технические соглашения

- **Шрифты — только локальные** из `public/fonts` через `src/shared/fonts`.
  Noto Sans SC подставляется фоллбэком автоматически — в текстах есть китайские
  названия, которых нет в Inter, Unbounded и Golos Text.
  Не подключай Google Fonts по сети: рендер не должен зависеть от сети,
  а `@font-face` через CSS `@import` Remotion не дожидается — кадр уедет
  системным шрифтом.
- **Время считаем в кадрах**, не в секундах: при смене fps композиции
  анимация не должна разъезжаться.
- **Случайность — только `random(seed)`** из Remotion, иначе рендер
  невоспроизводим.
- **Никаких `background-image`** — Remotion не ждёт загрузки картинки из CSS,
  и кадр может уйти без неё (правило `@remotion/no-background-image`).
  Картинка — `<Img>`, генеративная текстура — inline SVG-фильтр.
- **Цифры в кадре — через `CountUp`**, а не простым текстом: контент держится
  на статистике, а отсчёт удерживает зрителя до конца сцены.
- **Вертикальные позиции — через `vh()`**, горизонтальные — через `sp()`.
  Отступ «в долях ширины», применённый к низу вертикального кадра, поднимает
  элемент почти на середину.
- **Движение в кадре подкрепляй звуком** (`SoundCue`): появление плашки без
  щелчка читается как анимация, а не как монтаж.
- **`Root.tsx` не правим руками в блоках с маркерами** `new-composition:*` —
  туда пишет скрипт. Всё остальное в файле править можно.
- После изменений прогоняй `npm run lint` — `tsc` ловит несоответствие пропсов
  схемам до рендера.
