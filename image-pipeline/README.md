# Конвейер генерации изображений

Автоматическая генерация картинок по расписанию и передача их другому агенту.

## Как это устроено

```
image-pipeline/queue.json   ← заявки на генерацию (кладёте вы или агент-заказчик)
        │
        ▼
   Routine (cron) → новая сессия Claude Code → Higgsfield MCP
        │
        ▼
generated/<дата>/*.png      ← готовые файлы
generated/manifest.json     ← реестр: что сгенерировано, по какому промпту, кто забрал
```

Обмен идёт через git, а не через диск контейнера: сессия эфемерная, её файловая
система пропадает после завершения. Всё, что должно пережить запуск, коммитится
в ветку.

## Контракт для агента-потребителя

**Забрать новые картинки:**

1. Прочитать `generated/manifest.json`.
2. Отобрать записи со `status: "ready"`.
3. Скачать файл по `raw_url` (или взять из клона по `path`).
4. Проставить `status: "taken"`, заполнить `taken_by` и `taken_at`, закоммитить.

Пометка `taken` — единственный признак, что запись обработана. Без неё та же
картинка будет забрана повторно.

**Положить заявку:** добавить объект в массив `jobs` файла `queue.json` со
`status: "pending"` и закоммитить.

## Формат `queue.json`

```json
{
  "jobs": [
    {
      "id": "welding-robot-01",
      "prompt": "Professional editorial photograph of ...",
      "model": "marketing_studio_image",
      "aspect_ratio": "4:5",
      "count": 1,
      "status": "pending",
      "requested_by": "content-agent",
      "note": "для поста про промышленную автоматизацию"
    }
  ]
}
```

| Поле | Обязательное | Значение |
|------|--------------|----------|
| `id` | да | уникальный, латиницей, идёт в имя файла |
| `prompt` | да | промпт как есть, на английском |
| `model` | нет | по умолчанию `marketing_studio_image` |
| `aspect_ratio` | нет | по умолчанию `4:5` |
| `count` | нет | 1–4 варианта одного промпта, по умолчанию 1 |
| `status` | да | `pending` → `done` / `failed` |
| `requested_by` | нет | кто поставил заявку |
| `note` | нет | свободный комментарий |

## Формат `manifest.json`

```json
{
  "items": [
    {
      "id": "welding-robot-01",
      "path": "generated/2026-08-15/welding-robot-01.png",
      "raw_url": "https://raw.githubusercontent.com/Ostap-87/MyFirst/<ветка>/generated/2026-08-15/welding-robot-01.png",
      "prompt": "Professional editorial photograph of ...",
      "model": "marketing_studio_image",
      "aspect_ratio": "4:5",
      "width": 928,
      "height": 1152,
      "created_at": "2026-08-15T04:00:00Z",
      "status": "ready",
      "taken_by": null,
      "taken_at": null
    }
  ]
}
```

`status`: `ready` — готово к забору, `taken` — забрано потребителем,
`failed` — генерация не удалась (тогда есть поле `error`).

## Что делает Routine на каждом запуске

1. `git pull` ветки конвейера.
2. Читает `queue.json`, берёт заявки со `status: "pending"`.
3. Генерирует через Higgsfield, дожидается завершения.
4. Скачивает результат в `generated/<YYYY-MM-DD>/<id>.png`.
5. Дописывает запись в `manifest.json`, переводит заявку в `done`.
6. Коммитит и пушит.
7. Если очередь пуста — ничего не делает и не шумит.

## Ограничения, о которых нужно помнить

- **Минимальный интервал расписания — один час.** Чаще запускать нельзя.
- **Кредиты Higgsfield конечны.** Тариф Starter, на момент настройки ~200
  кредитов. Лёгкая генерация — единицы кредитов, тяжёлые модели — десятки.
  В `queue.json` стоит держать разумное число заявок за запуск, иначе баланс
  уйдёт за пару суток. Рекомендуемый потолок — 5 картинок за запуск.
- **Авторизация MCP.** Higgsfield подключён через MCP. Если в фоновом запуске
  сервер окажется неавторизованным, генерация упадёт — заявка получит
  `status: "failed"` с текстом ошибки, а не молча пропадёт. Первый запуск нужно
  проверить руками.
- **Конфликты git.** Если потребитель и генератор пишут в манифест
  одновременно, возможен конфликт. Поэтому потребитель правит только поля
  `status`/`taken_by`/`taken_at`, а генератор только добавляет новые записи в
  конец — так слияние остаётся тривиальным.
- **Время в cron — UTC.** Московское время = UTC+3, то есть 09:00 МСК это
  `0 6 * * *`.
